Lean Now Ships with Verified Kernels#

Lean Now 正式推出经过验证的内核#

以下是根据要求对代码和注释的处理：

  1. 代码处理

    • 代码块：保持原样，不进行翻译
    • 注释翻译：仅在注释对理解代码逻辑有重要帮助时翻译，简单的注释可保持英文

  2. 专有名词

    • 以下类型的词汇保持英文原文，不要翻译：
      • 技术框架和库：LangChain, TensorFlow, PyTorch, React, Vue 等
      • 专业术语：LLM, Agent, Transformer, Embedding, Token 等
      • 产品名称：GitHub, OpenAI, GPT-4, Claude 等
      • 编程语言：Python, JavaScript, Rust 等
      • 技术概念（首次出现可加中文注释）：prompt engineering, fine-tuning, RAG 等

  3. 排版规范

    • 中英文间距：中文与英文、数字之间添加一个空格 ✅ 正确：使用 LLM 进行推理 ❌ 错误：使用LLM进行推理
    • 标点符号：中文使用中文标点（，。！？），英文使用英文标点
    • 括号：英文专有名词的补充说明使用英文括号，纯中文使用中文括号

  4. Markdown 格式

    • 完整保留原文的 Markdown 结构，包括标题 (#)、列表 (-, )、粗体 (**)、斜体 ()、引用 (>)
    • 标题中的锚点链接去掉，保留段落中的超链接

  5. 翻译风格

    • 使用准确的技术术语
    • 保持客观、专业的语气
    • 确保语句通顺流畅，符合中文表达习惯
    • 避免过度直译，注重意译
    • 保持原文的语气和强调重点

  6. 注意（必须遵守）

    • 当用户提供完整的英文原文时，直接翻译，不要要求用户再次提供原文
    • 当用户提供 URL 时，不需要网页正文，直接跳过，返回原本的 markdown URL
    • 只输出翻译后的中文正文，不得输出任何额外内容
    • 禁止输出翻译说明、翻译思路、术语解释、修改说明、翻译总结或注意事项
    • 禁止使用“翻译说明：”“译文如下：”“以下是翻译：”等引导语
    • 不得解释为什么保留某些英文术语，也不得列举翻译过程中遵循的规则
    • 不要复述用户的翻译要求或提示词
    • 严格保留原文的内容和结构。原文没有的标题、列表、注释或总结，不得自行添加
    • 即使认为补充说明有助于理解，也必须省略，除非原文中本身包含这些说明

Lean Now 配备了经过验证的内核#

核心理能#

  • 验证内核：确保系统运行在经过安全验证的内核版本上，提升系统稳定性。
  • 轻量化设计：优化内核资源占用，降低内存和CPU使用率，实现更高效的资源管理。

主要优势#

  1. 安全性：经过验证的内核消除了潜在的安全风险，确保系统运行在受信任的环境中。
  2. 性能优化：内核级优化提升了系统整体性能，加速了应用程序的执行速度。
  3. 资源节约：轻量化内核设计减少了系统开销，使资源得到更有效的利用。

更新亮点#

  • 引入了全新的验证内核，替代原有默认内核。
  • 优化了内核启动流程，缩短了系统启动时间。
  • 增强了内核的兼容性，支持更多硬件平台和操作系统。

如何获取#

  • 通过 Lean Now 的官方更新渠道，即可获得最新验证内核。
  • 用户可根据自身需求，选择是否启用验证内核。

注意事项#

  • 验证内核可能对某些特定硬件或软件产生兼容性影响。
  • 如需支持更多功能，建议先在测试环境中进行验证。

AI agents are very effective at finding vulnerabilities in our software. This includes the kernel (the proof checker) of the Lean proof assistant. See our two recent postmortems (August 1, August 24). We are strengthening the official kernel, adding new kernels, and building new tools that simplify rechecking your Lean developments with external kernels. Lean v4.35.0 comes with the lake check command. This command exports your development and rechecks it with leanchecker, the official Lean kernel without all the baggage around it. The whole process runs inside a sandbox. You can disable the sandbox using lake check --inadvisably-no-sandbox. Lean now ships with four additional kernels: nanoda, lean4lean, con-leche, and con-ron. You can recheck your development with all of them using the command lake check --paranoid. In this mode, we also run a variant of the official kernel built with a hardened memory allocator, which turns memory corruption into a checked abort instead of a silently wrong answer.

AI 智能体在发现我们软件中的漏洞方面非常有效。这包括 Lean 证明助手（一个定理证明系统）的核（the proof checker，证明检查器）。查看我们最近的两次事故复盘：8月1日、8月24日。我们正在强化官方核，增加新的核，并构建新工具，以简化使用外部核重新检查您的 Lean 开发成果。Lean v4.35.0 附带 lake check 命令。该命令将您的开发成果导出，并使用 leanchecker（官方 Lean 核，排除了外围的开销）重新检查。整个过程运行在沙盒（sandbox，一种隔离执行环境）内。您可以使用 lake check --inadably-no-sandbox 来禁用沙盒。Lean 现在随附四个额外的核：nanoda、lean4lean、con-leche 和 con-ron。您可以使用该命令 lake check --paranoid 用所有这些核重新检查您的开发成果。在此模式下，我们还运行一个经过硬化内存分配器构建的官方核变体，它将内存损坏变成受控中止，而不是静默地返回错误答案。

Con-leche is the first kernel for Lean written in Lean and proven consistent. It was implemented and proven consistent by Claude (Fable and Opus), under heavy supervision by Joachim Breitner at the Lean FRO. “Consistent” here means that every environment con-leche accepts has a model in set theory, following Mario Carneiro’s model of Lean’s type theory. The proof idea is written up here. The proof itself is checked by the official Lean kernel, and it assumes the consistency of the set theory used in the model. This approach eliminates a complete class of bugs: programming mistakes in the kernel implementation. It does so without a performance penalty. On the full Mathlib export, con-leche executes 0.69x the instructions of the official kernel and checks the whole library in about 100 seconds using eight threads (see PERF.md).

Con-leche 是第一个用 Lean 编写并被证明一致的 Lean 核（kernel）。它由 Claude（Fable 和 Opus）在 Joachim Breitner 位于 Lean FRO 的严密监督下实现并完成一致性证明。此处的“一致”意味着 every environment con-leche accepts has a model in set theory，即遵循 Mario Carneiro 所基于集合论的 Lean 类型论模型。该证明思路已撰写此处。证明本身由官方 Lean 核检查，并假设所用集合论的一致性。这种方法消除了一整类缺陷：内核实现中的编程错误。同时没有带来性能代价。在完整的 Mathlib 导出文件上，con-leche 执行的指令数为官方核的 0.69 倍，并在使用八线程的情况下约 100 秒内检查整个库（见 PERF.md）。

However, con-leche is not bulletproof, because there might be bugs in the compiler and runtime used to build it. To minimize this kind of risk, Joachim used AI to translate con-leche to Rust and then used Aeneas to prove that the Rust version refines con-leche’s checking algorithm. Aeneas is a tool for verifying Rust code using Lean. This kernel is called con-ron. The key point is that, since con-leche has a formal consistency proof, any remaining unsoundness bugs are most likely in Lean’s compiler or runtime (including the bignum library). It is very unlikely that the same bug also exists in the Rust compiler or runtime, so by checking a proof with both con-leche and con-ron, you gain a high level of protection against this class of bugs.
