2035提前到来

2026-11-25
  • 原文 2035 came early

tl;dr trynix.dev boots GUI programs now. Try solitaire, GL gears, xeyes, a voice, the weather over curl, or Firefox.

tl;dr trynix.dev 现在启动 GUI 程序。 尝试 solitaire, GL gears, xeyes, a voice, the weather over curl, 或 Firefox

I remember watching the talk The Birth & Death of JavaScript by Gary Bernhardt and falling in love with the whimsical yet dreadfully serious unfolding of the story of how JavaScript will come to dominate all software.

我记得观看了 The Birth & Death of JavaScript 由 Gary Bernhardt 并爱上了 JavaScript 将如何统治所有软件的故事的俏皮但令人敬畏的严肃展开。

Others have noted the inevitability of JavaScript’s dominance, so perhaps it was not surprising that Atwood’s Law holds true.

其他人已经指出 JavaScript 的主导地位不可避免，所以 Atwood’s Law 仍然成立，这或许并非出乎意料。

Atwood’s Law Any application that can be written in JavaScript, will eventually be written in JavaScript. — Jeff Atwood, 2009

Atwood 定律 任何能够用 JavaScript 编写的应用，最终都会被用 JavaScript 编写出来。 — Jeff Atwood, 2009

I highly recommend watching the talk if you have not already seen it, but the short and skinny is a lookback from 2035 and how JavaScript came to be the defacto language for all software.

如果你还没有观看过这场演讲，我强烈推荐你观看；简短概括是 2035 年的回顾以及 JavaScript 如何成为所有软件的事实上的编程语言。

In Bernhardt’s retelling of events, the date is worked back from 2035, however unsurprisingly, large language models have rapidly sped up the timeline. What was once perceived to be the end-state at 2035 has arrived years earlier and you can witness it unfolding at trynix.dev.

在 Bernhardt 对事件的复述中，日期是从 2035 年倒推出来的，但不出所料，大语言模型迅速加速了这一时间线。曾被视为 2035 年终态的情形已提前数年到来，你可以在 trynix.dev 见证它逐步展开。

JavaScript 战争 JavaScript 消失 trynix, Nov 2026 asm.js GIMP 在标签页中 METAL 十天内编写； 每个浏览器都运行它 2020 至 2025： 五年一事无成 没有人写它； 一切都运行在它上 Firefox 在 Linux 上， 在浏览器标签页中 C 和 C++ 编译到它 接近原生速度 桌面程序 为 web 编译 浏览器的 VM 成为操作系统 1995 2005 2015 2025 2035

One of the most impressive creations I’ve managed to build leveraging nixpkgs-multiverse is https://trynix.dev.

我利用 nixpkgs-multiverse 构建出的最令人印象深刻的成果之一是 https://trynix.dev。

It still baffles my mind that I can run any Nix package, over 300,000 distinct package versions, straight from my browser. Truly insane capability. I was however a little dismayed at the speed of the QEMU emulation in the browser. It was slow enough that the creation tipped more towards novelty than practicality.

这仍然令人费解，我竟然可以直接从我的浏览器中运行 任何 Nix 软件包，包含超过 300,000 个不同的软件包版本。这真是一种疯狂的能力。不过，对于我在浏览器中 QEMU 模拟的速度，我有点小失望。它慢到，创建过程更偏向新奇，而不是实用。

I woke on November 20th and saw Domen Kožar sharing a single message in our TacoSprint Discord channel: unkernel.dev

11 月 20 日醒来时，我看到 Domen Kožar 在我们的 TacoSprint Discord 频道里发了一条消息：unkernel.dev

It was the fast browser Linux experience I had sought to achieve, but with Nix.

我追求获得快速的 Linux 浏览器体验，但使用 Nix。

In an AI induced manic frenzy, I adopted the new engine along with a slough of long-wished features almost immediately.

在 AI 诱导的狂热中，我几乎立即采用了新引擎，并配上了许多向往已久的功能。

The proof is in the pudding: unkernel delivers remarkable speed improvements overqemu-wasm,1especially on first runs where kernel work dominates. The new engine is able to deliver 2x to 32x faster performance depending on the workload.2

最终的证明来自实际结果： unkernel 相比qemu-wasm，1，尤其是在首次运行时，此时内核工作占主导。

新引擎能够根据工作负载提供 2x 到 32x 的速度提升。2

JavaScript & WebAssembly nirvana.

JavaScript 和 WebAssembly nirvana。

Amazingly not only does the kernel boot quickly, it also enables networking, full-fledged graphical and audio experiences directly in the browser.

令人惊叹的是，不仅内核启动速度快，而且直接在浏览器中实现了网络连接、完整的图形和音频体验。

Windows.A program’s Wayland surfaces are composited in the page bywland, and they float over the terminal you started them from.

Windows.程序的 Wayland surface 由wland合成到页面中，并且会浮现在你启动它们的终端上方。

GL.The VM includes a minimal Mesa build with only the virgl driver, compiled to WebAssembly, rendering through your browser’s WebGL2.

GL.VM 包含一个仅包含 virgl 驱动的极简 Mesa 构建，编译为 WebAssembly，并通过浏览器的 WebGL2 进行渲染。

Sound.The VM has an ALSA sound card, and can play audio through your browser.

声音。VM 有一块 ALSA 声卡，并且能够通过你的浏览器播放音频。

Network.curl,git cloneandpip installwork. Each TCP connection goes over one WebSocket to aWisprelay.3

网络。curl,git clone和pip install可工作。 Each TCP 连接通过单个 WebSocket 向Wisp中继发送。3

The best joke in Bernhardt’s talk is a browser running inside another browser: the Windows GIMP under Wine, in Chrome, in Firefox. Of course, I had to try it with trynix. 😈

Bernhardt 演讲中最精彩的梗是浏览器套浏览器：在 Firefox 里跑 Chrome，在 Chrome 里跑 Wine，在 Wine 里跑 Windows 版 GIMP。当然，我必须用 trynix 试一把。😈

Here isFirefox in trynix, and it loadingtrynix.dev, and then loading Firefox again inside itself.4

这里是Firefox in trynix，它正在加载trynix.dev，随后又在自身内部再次加载 Firefox。4

Sit and bask in that insanity. That is Firefox, on Linux compiled to WebAssembly, in a Firefox tab, loading the site and then loading Firefox again inside itself. 🤯

坐下来，感受那份疯狂吧。那是 Firefox，在 Linux 编译为 WebAssembly 中，在一个 Firefox 标签页中，正在加载该站点，然后再次将 Firefox 加载到其自身之内。🤯
